
# Обратные вызовы (`Completion handler`)

## Что такое `Completion` простыми словами

Представь, что ты послал друга в магазин за минералкой. 

Ты не будешь стоять и ждать его у двери, ничего не делая. Ты скажешь: 

> Сходи за хлебом, а когда вернёшься — постучи в дверь

Вот этот стук в дверь и есть **completion handler (обратный вызов).**

**Completion** — это способ сказать программе: "Сделай эту работу, а когда закончишь — позови меня, я пока занят другими делами"

## Обычная функция, без **completion**

Давайте вначале рассмотрим пример функции, которая работает без `completion`

Представим, что у нас есть экран, с полем ввода, в которое пользователь может ввести абсолютно любое число, а мы в ответ должны вернуть индекс (порядковый номер элемента в массиве) этого числа.

Например у нас есть массив чисел – `[0,3,11,11,5]`, пользователь вводит число 10, значит индекс этого элемента – `nil`

 - Число `3` – Индекс `2`
 - Число `11` – Индекс `2` 
 - Число `11` – Индекс `2`
 - Число `5` – Индекс `4`

и так далее.

**Вот как выглядит функция, которая выполняет эти действия.** 

*Так как мы не знаем, какое именно число введёт пользователь и в каком массиве мы будем его есть – вынесем эти значения в параметры функции.*

*Таким образом наша функция, будет способна искать абслютно любое число, в абсолютно любом массиве, без привязки к конкретным значения.*

*При вызове функции, мы уже укажем конкртеные значения числа и массива*

```swift
///  `findIndex` Название нашей функции
///
///  - Parameters:
///  - number: Число, которое вводит пользователь
///  - array: Массив чисел, внутри которого нужно найти данное число
///
///  - Returns: Вернём индекс найденного числа
///
func findIndex(of number: Int, in array: [Int]) -> Int? {    
    // enumerated() превращает массив в пары (индекс, элемент)
    // Например, массив [10, 20, 30] превращается в:
    // (0, 10), (1, 20), (2, 30)
    for (index, element) in array.enumerated() {
        
        // Сравниваем текущий элемент с тем числом, которое ищем
        if element == number {
            
            // Ура! Нашли совпадение.
            // Возвращаем индекс прямо из цикла и выходим из функции
            return index
        }
        // Если не совпало — переходим к следующему элементу
    }
    
    // Если мы дошли до этой строчки, значит, весь массив проверили
    // и ничего не нашли. Возвращаем nil (пустое значение)
    return nil
}
```


## Как пользоваться этой функцией

Допустим, у нас есть массив чисел:

```swift
let numbers = [10, 23, 143, 67, 89]
```
И мы хотим найти, на каком месте стоит число 143. Пишем:

```swift
if let position = findIndex(of: 45, in: numbers) {
    print("Число 45 найдено на позиции \(position)")
} else {
    print("Такого числа нет в массиве")
}
```
Будет выведено: `"Число 45 найдено на позиции 2"`

Почему `2`? Потому что в программировании счёт всегда начинается с нуля. 

Первый элемент `(10)` — это позиция `0`. Второй элемент `(23)` — позиция `1`...


## Почему функция возвращает `Int?` (с вопросом)

Вопрос после `Int` означает, что результат может быть либо числом (индексом), либо `nil`

Это называется опциональный тип. Если бы функция просто возвращала `Int`, **она обязана была бы вернуть какое-то число даже тогда, когда ничего не найдено**. 

А что возвращать? Минус один? Это неудобно и сбивает с толку.

**Поэтому `Swift` придумал опционалы: если есть результат — отдаём число. Если результата нет — отдаём `nil`.** 

`nil` переводится как "ничего", "пустота", "отсутствие значения".

## Как читать сигнатуру функции

```swift
func findIndex(of number: Int, in array: [Int]) -> Int?
```

Читается так: "Функция `findIndex`, у которой первый параметр называется `of` и имеет тип `Int`, второй параметр называется `in` и имеет тип массив `Int`. 

Возвращает функция `опциональный Int.`"

**Почему в функции два имени параметра ?** 

Дело в том, что `Swift` позволяет нам использовать `внешнее` и `внутрее` название параметра.

В нашем случае  – при вызове функции у нас получится красивое английское предложение: `findIndex of 45 in numbers` — "найти индекс 45 в массиве numbers".  

Пример вызова:

```swift
let index = findIndex(of: 4, in: [0,1,2,3])
```

Это звучит красивее, чем если бы мы использовали один параметр – 

```swift
func findIndex(number: Int, array: [Int]) -> Int?
```

Пример вызова:

```swift
let index = findIndex(number: 4, array: [0,1,2,3])
```

`findIndex number 45 array numbers`

 - `of` и `in` – внешние параметры, мы будем их использовать при вызове функции
 - `number` и `array` – внутренние, мы будем их использовать при работе внутри функции

Для начала – вам не обязательно заморачиваться этим, вы можете использовать один параметр.

## Частые ошибки новичков

**Ошибка 1.** 
Забыть про опциональный результат. Нельзя просто написать let pos = findIndex(...) и использовать pos как число. Нужно обязательно проверить через if let.

**Ошибка 2.** 
Думать, что индекс всегда существует, забывать о том, что элемента просто может не быть в массиве.

**Ошибка 3.** 
Путать индекс и значение. Индекс — это позиция в массиве (0, 1, 2). Значение — это то, что лежит по этому индексу. Функция возвращает индекс.

**Ошибка 4.** 
Не закрывать фигурные скобки. Каждая открытая скобка должна быть закрыта.

## Заключение

Функция `findIndex` — это учебная версия настоящей встроенной функции `firstIndex(of:)`
 
 Она делает очень простую работу: проходит по массиву от начала до конца, сравнивает каждый элемент с искомым, и как только находит совпадение — возвращает его индекс. 

Если доходит до конца и ничего не находит — возвращает `nil`

# Функция `firstIndex(where:)` — как она работает под капотом

## Что делает эта функция

В отличие от обычного поиска по точному совпадению, функция `firstIndex(where:)` ищет **позицию первого элемента, который подходит под какое-то условие.** 

Ты не говоришь "найди число 45". 

Ты говоришь "найди первое число, которое больше 40". Или "найди первую строку, которая начинается на букву А". 

**Условие может быть любым.**

## Простая версия для понимания

Вот как мы могли бы написать такую функцию сами. Она ищет индекс числа, которое соответствует условию.

```swift
func findFirstIndex(where condition: (Int) -> Bool, in array: [Int]) -> Int? {
    
    // Проходим по массиву с индексом и значением
    for (index, element) in array.enumerated() {
        
        // Проверяем: подходит ли текущий элемент под условие?
        if condition(element) == true {
            
            // Подходит! Возвращаем индекс
            return index
        }
        // Не подходит — идём дальше
    }
    
    // Ничего не подошло — возвращаем nil
    return nil
}
```

Эта функция несколько сложнее – в параметре появляется `Completion`

```swift
condition: (Int) -> Bool
```

Зачем это нужно ? 

В первом случае, когда мы искали число в массиве – всё было просто, пользователь указывает число, мы его находим.

```swift
let index = findIndex(number: 4, array: [0,1,2,3])
```

Но сейчас ситуация иная – **мы должны найти не просто совпадение элементов, а найти любое условие, которое только вздумается пользователю**. 

И разумеется мы и догадаться не можем, что именно придёт ему в голову – мб он захочет найти число `10`, а мб число, которое меньше `5`, а мб число, которое делится без остатка на `12342323423423434563549645645`

Всё это способен воплотить в себе `Completion`

```swift
condition: (Int) -> Bool
```

Данный комплишен принимает в себя какое-то число (`Int`) а в ответ ожидает услышать решение (`-> Bool`) по этому числу.

Обязательно вернитесь к функции `findFirstIndex(where` , которая написана выше и обратите внимание что мы передаём в `condition`

В `condition` мы передаём каждый элемент из массива и ожидаем решения по нему. 

Решение, устраивает ли нас это число – лежит на стороне вызова функции.

Звучит не просто, нужно практиковаться!

## Как пользоваться этой функцией

Допустим, у нас есть массив чисел:

```swift
let numbers = [3, 7, 12, 5, 9, 20, 4]
```

Мы хотим найти позицию первого числа, которое больше `10`. Пишем:

```swift
if let index = findFirstIndex(where: { number in
	/// Здесь происходит обработка нашего Completion
	/// number это то, что мы передали в Comletion на этом шаге:
	/// if condition(element)... (Функция findFirstIndex(where)
	/// т.е. number здесь это тот element, что мы передали в самой функции

    /// Возвращаем Bool как того требует Completion
    /// И говорим, что нас устроит число, которое больше 10
    /// Верни его индекс
    return number > 10
}, in: numbers) {
    print("Первое число больше 10 найдено на позиции \(position)")
} else {
    print("Нет чисел больше 10")
}
```

Что выведет программа? 

*"Первое число больше 10 найдено на позиции 2".*

## Что значит `condition: (Int) -> Bool`

Это параметр, который принимает функцию. 

Стрелочка означает "возвращает". 

Читается так: "параметр с именем `condition`, который является функцией, принимающей `Int` и возвращающей `Bool` (правда или ложь)".

Внутри себя наша функция вызывает эту переданную функцию для каждого элемента массива.

`condition(element)` — это вызов комплишена, а логика тела комплишена указывается при вызове самой функции.


## Пример с поиском чётных чисел

Найти позицию первого чётного числа в массиве:

```swift
let numbers = [3, 7, 12, 5, 9, 20, 4]

if let position = findFirstIndex(in: numbers, where: { number in
    /// Прописываем логику Комплишена
    /// Нужен индекс первого числа, которое делится без остатка на 2
 	number % 2 == 0 
}) {
    print("Первое чётное число на позиции \(position)") // Выведет: позиция 2
}
```
Знак `%` называется "остаток от деления". `$0 % 2 == 0` означает "число делится на `2` без остатка", то есть чётное.

Благодаря Completion мы можем прописывать любое условие поиска.
]

## Отличие от обычного `firstIndex(of:)`

Обычный `firstIndex(of:)` ищет точное совпадение. Ты должен знать, какое именно число или строку ищешь.

`firstIndex(where:)` ищет по условию. Ты описываешь правило. Это гораздо гибче.

Сравни:

```swift
let numbers = [3, 7, 12, 5, 9]

// Точный поиск — ищем конкретное число 12
if let index = numbers.firstIndex(of: 12) {
    print("Число 12 на позиции \(index)")
}

// Условный поиск — ищем первое число больше 10
if let index = numbers.firstIndex(where: { number in
	/// Условие поиска
	number > 10
}) {
    print("Первое число больше 10 на позиции \(index)")
}
```

Второй вариант намного мощнее, потому что условие может быть любым: "больше 10", "делится на 3", "заканчивается на 5", "начинается с буквы К".


## Короткое резюме

Функция `firstIndex(where:)` проходит по массиву от начала к концу. Для каждого элемента она вызывает переданное тобой замыкание-условие. Как только замыкание возвращает `true` — функция немедленно возвращает индекс этого элемента. Если до конца массива ни разу не вернулось `true` — возвращается `nil`

Это очень полезная функция, потому что позволяет искать не только точные совпадения, но и любые ситуации, которые ты можешь описать в коде. 

"Найди первую задачу, которая просрочена", "найди первого пользователя младше 18 лет", "найди первое слово длиннее 10 букв" — всё это делается через `firstIndex(where:)`

## Передача из одного экрана в другой через `Completion`

Представь, что у тебя есть `Экран А` с кнопкой, а после нажатия открывается `Экран Б`. Когда пользователь что-то делает на `Экране Б` — нужно передать результат обратно на `Экран А`.

### Проблема

Обычный переход между экранами не позволяет легко передать данные обратно. 

`Экран А` открыл `Экран Б`, но как `Экран Б` скажет `Экран А`: 

"Пользователь выбрал вот это"?

### Решение с `completion`

Вот как это работает по шагам:

**Шаг 1.** 
Экран А создаёт специальное место для хранения результата — переменную, которая пока пустая.

**Шаг 2.** Когда пользователь нажимает кнопку выбора, Экран А открывает Экран Б и при открытии передаёт ему замыкание. Это замыкание содержит всего одну строчку: "когда пользователь что-то выберет — положи результат в мою переменную".

**Шаг 3.** Экран Б открывается и запоминает переданное замыкание. Он показывает пользователю список вариантов.

**Шаг 4.** Пользователь выбирает какой-то вариант. Экран Б вызывает сохранённое замыкание и передаёт в него выбранный вариант. Потом Экран Б закрывается.

**Шаг 5.** Замыкание на Экране А выполняется. Переменная, которая была пустая, теперь содержит выбранный пользователем вариант. Экран А видит, что переменная изменилась, и обновляет интерфейс.

### Живой пример

Представь приложение для выбора событий. На главном экране написано "Ничего не выбрано". Пользователь нажимает кнопку "Выбрать событие", открывается список: Концерт, Выставка, Вечеринка. Пользователь нажимает "Концерт". Экран выбора закрывается, и на главном экране теперь написано "Выбрано: Концерт, 15 мая".

Вся магия происходит именно через completion. Экран выбора не знает, какой экран его открыл, и не знает, что делать с выбранным значением. Он просто вызывает переданный ему блок кода и передаёт туда выбор. А какой код был передан — решает тот экран, который открыл окно выбора.

## Как передать текст из поля ввода

Представь экран, где пользователь вводит своё имя. Ты открываешь этот экран с клавиатурой, пользователь печатает имя и нажимает "Сохранить". Экран закрывается, и на предыдущем экране появляется приветствие с этим именем.

Алгоритм такой же. Открывающий экран передаёт замыкание: "сохрани введённое имя в мою переменную". Экран ввода сохраняет это замыкание. Пользователь вводит имя и нажимает кнопку. Экран ввода вызывает замыкание, передаёт туда текст из поля. Замыкание сохраняет текст в переменную. Открывающий экран обновляется и показывает "Привет, имя!" вместо "Привет, Гость!".

## Что означает слово escaping

В некоторых языках программирования нужно специально пометить completion словом escaping. Оно означает, что замыкание "убегает" из функции. Функция закончит свою работу, а замыкание останется в памяти и вызовется позже.

Без escaping замыкание должно выполниться ДО того, как функция завершится. Но в нашем случае с асинхронными операциями (загрузка из интернета, ожидание ввода пользователя) замыкание выполняется ПОСЛЕ того, как функция уже завершилась. Поэтому escaping необходим.

## Коротко о главном

Completion — это способ сказать "сделай работу, а когда закончишь — выполни вот этот блок кода". Через completion можно передавать данные из одного экрана на другой. Экран Б не знает, какой экран его открыл, он просто вызывает переданный ему блок кода. Открывающий экран решает, что делать с полученными данными, описывая это внутри замыкания.

Это фундаментальный паттерн в разработке приложений. Когда ты выбираешь дату в календаре, выбираешь фото из галереи, подтверждаешь удаление или вводишь текст — почти всегда за этим стоит completion handler.

## Где это применяется в реальных приложениях

Выбор даты в календаре — выбрал дату, вернул её на предыдущий экран. Выбор фото из галереи — выбрал картинку, вернул изображение. Вход в аккаунт — ввел логин и пароль, вернул данные пользователя. Загрузка ленты постов — скачал посты из интернета, отобразил их на экране. Сканирование QR-кода — считал код, вернул текст.

Везде, где есть ожидание результата — там нужен completion или его современные аналоги.

## Что дальше

Completion — это первый шаг в мир асинхронного программирования. Когда ты освоишь его, можно переходить к более современным инструментам: Promise, async и await. Они решают те же задачи, но код становится чище и понятнее. Однако completion остаются важным знанием, потому что множество старых и даже новых API построены именно на них.
