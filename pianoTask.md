
# Кнопка бронирования

## Введение

Давайте рассмотрим классический пример, с которым сталкивается каждый разработчик при создании приложения с бронированием.

**Задача:** 
Вам необходимо забронировать дату для посещения определённого места. Пусть это будет класс игры на пианино.

Какова последовательность действий, которая приведёт вас к желаемому результату? 

Давайте разберём по шагам.


## Шаг 1. Определяем ожидаемое поведение

Прежде чем писать код, нужно чётко понимать, какое поведение мы ожидаем в итоге.

В нашем случае (Бронирование класса с фортепиано) перед нами будет список кнопок, с конкретным временем для записи: 

 - `10:00`
 - `11:00`
 - `12:00`
 - и так далее

и большая кнопка 

`Забронировать`


**Требование:** 

Когда пользователь нажимает на кнопку записи (`12:00`, к примеру) – кнопка должна стать синего цвета, что будет свидетельствовать о том, что именно она выбрана.

После того как пользователь нажмёт  `Забронировать` – мы должны сделать `кнопку записи` более недоступной для выбора и в этом нам поможет свойство `.disabled`, благодаря которому мы можем заблокировать кнопку.


## Шаг 2. Создаём первую версию кнопки

Начнём с самого простого — создадим кнопку, которая отображает время:

```swift
struct TimeButton: View {

    var body: some View {
        Button("12:00") {
            // Обработка нажатия
        }
        .padding(8)
        .background(.blue)
        .foregroundStyle(.white)
        .cornerRadius(8)
    }
}
```

### ❌ Какие проблемы мы видим?

| Проблема | Описание |
|:---------|:---------|
| Жёстко заданное время | Кнопка всегда показывает время "12:00" |
| Фиксированный цвет | Кнопка всегда синяя, независимо от состояния |
| Нет обратной связи | Пользователь не видит, забронировано время или нет |

**Дело в том, что любой параметр `View` который может поменяться мы должны вынести в отдельное поле.**

В нашем случае, очевидно, что **меняться будет время на кнопке**. Помимо этого, **меняться должен и цвет кнопки**.

## Шаг 3. Улучшаем кнопку — добавляем параметры

Очевидно, что время записи не может быть жёстко привязанным. 
Мы должны уметь показывать **абсолютно любой час**.

Кроме того, цвет кнопки не может быть всегда синим. 
Он должен меняться в зависимости от доступности времени:

| Состояние | Цвет | Поведение |
|:----------|:-----|:----------|
| Доступно | Синий | Можно нажать |
| Забронировано | Серый | Недоступно для нажатия |

### ✅ Улучшенная версия

```swift
// MARK: - Кнопка для записи

struct TimeButton: View {
    
    /// Время записи
    let time: String
    
    /// Доступно ли время для бронирования?
    let isAvailable: Bool
    
    var body: some View {
        Button(time) {
            // Обработка нажатия
        }
        .padding(8)
        .background(isAvailable ? .blue : .gray)
        .foregroundStyle(.white)
        .cornerRadius(8)
        .disabled(!isAvailable)
    }
}
```
### 📝 Что изменилось?

| Поле | Назначение |
|:-----|:-----------|
| `time` | Теперь мы можем передать любое время и кнопка его отрисует |
| `isAvailable` | Регулирует цвет и доступность кнопки |

Благодаря полю `isAvailable` мы будет получать текущее состояние кнопки – доступна ли она для нажатия или же нет.

В этом нам помог тернарный оператор

```swift
.background(isAvailable ? .blue : .gray)
```

Но что если логика цвета несколько сложнее ?

В таком случае мы можем выделить отдельное `computed property` внутри которого регулировать цвет в зависимости от условий:

```swift
**var** backgroundColor: Color {  
/// Если кнопка доступна для выбора  
**if** isAvailable {  
**return** .orange  
}  
  
/// Если кнопка выбрана пользователем  
**if** isSelected {  
**return** .blue  
}  
  
/// Во всех остальных случаях  
**return** .gray  
}
```

Как только сработает любое из условий `return` код дальше не пойдёт.

В тоге получится следующее:

```swift
.background(backgroundColor)
```

**Конкретные значения для `time` и `isAvailable` мы укажем, когда будем добавлять кнопку на экран, пока мы лишь определили кодом как она должна выглядеть в зависимости от указанных значений.**

Конкретное значения нас совсем не интересуют, нам достаточно лишь знать, что:

| Поле | Назначение |
|:-----|:-----------|
| `time: String` | Любая строка |
| `isAvailable: Bool` | `true` / `false` |


## Шаг 4. Показываем несколько кнопок

Кнопку мы нарисовали, но пока не добавили её на экран.

Кнопок может быть несколько — человек может записаться в любое время, например, с 9:00 до 17:00.

### Создаём массив с доступными временами

Раз кнопок может быть несолько – нам не обойтись без массива:

```swift
let times: [String] = ["9:00", "10:00", "11:00", "12:00", "13:00", "14:00"]
```

### Используем `ForEach` для отображения списка

Благодаря такому визуальному компоненту как `ForEach` мы можем отрисовать элемент, который будет повторяться на экране столько же раз сколько и элементов в указанном массиве.

```swift
// MARK: - Список всех кнопок

struct TimeButtonList: View {
    
    /// Доступные времена для записи
    let times: [String] = ["9:00", "10:00", "11:00", "12:00", "13:00", "14:00"]
    
    var body: some View {
        ForEach(times, id: \.self) { currentTime in
            /// Передаём в кнопку реальные данные для time и isAvailable
            TimeButton(time: currentTime, isAvailable: true)
        }
    }
}
```

`currentTime` это каждое время из массива `times` по очереди.

Надеюсь, вы помните, что для кнопки `TimeButton` которую мы рисовали в самом начале, необходимо указать `время` и `доступна ли она`

**Именно это мы и указываем, когда добавляем её на экран:**

### 📝 Что здесь происходит?

| Компонент | Роль |
|:----------|:-----|
| `ForEach` | Проходит по массиву и создаёт кнопку для каждого элемента |
| `currentTime` | Текущий элемент массива (например, `10:00`, `11:00`,`...`) |
| `isAvailable` | Доступна ли кнопка ? |
| `id: \.self` | Уникальный идентификатор для каждого элемента |

## Шаг 5. Проблема с `isAvailable`

Заметьте: сейчас мы всегда передаём `isAvailable: true`, что не соответствует реальности. Ведь время рано или поздно может стать недоступным для бронирования.

### ❌ Текущая проблема

```swift
TimeButton(time: currentTime, isAvailable: true)  // всегда true — не правильно!
```
Вопрос: 
**Как определять, доступно ли конкретное время?**

Ответ: 
Логика доступности должна храниться **вне** кнопки и передаваться ей через параметр. 

**Кнопка — это лишь визуальный компонент, она не должна сама решать, доступно время или нет.**

Задача кнопки – показать время и текущее визуальное состояние (в нашем случае благодаря параметру `isAvailable`  мы регулируем цвет – либо синий / либо серый), но вот что конкретно указать для `isAvailable` при отрисовке кнопки – пока не понятно.

## Шаг 6. Композиция экрана

Важно понимать, что `TimeButton` — это лишь **часть общей композиции**. 
На экране может быть много разных элементов:

- Календари
- Текста
- Списки
- Картинки
- и так далее...

Основное `View` (`BookingView`) занимается тем, что собирает все эти элементы воедино и показывает на экране телефона.

```swift
// MARK: - Основное Вью, которое собирает всех компоненты на экране воедино 

struct BookingView: View {
    
    /// ВьюМодель, где хранится наша логика
    @StateObject private var viewModel = BookingViewModel()
    
    var body: some View {
        /// Помещаем на экран наш список с кнопками
        TimeButtonList(timeSlots: $viewModel.timeSlots)
      }
}
```

Обратите внимание на последовательность представления:

 1. У нас есть основное Вью – `BookingView` 
 2. Внутри которого мы показываем `TimeButtonList` 
 3. Внутри `TimeButtonList` мы уже отрисовываем все наши кнопки `TimeButton`

Такой подход позволяет чётко структурировать взаимосвязь между вью и не превращать `body` в бесконечное безобразие. 

**Каждый из элементов – представляет собой полностью независимый компонент, который можно с лёгкостью переиспользовать и на других экранах.**

## Шаг 8. Реализуем логику `isAvailable` через структуру данных

Теперь, когда мы разобрались с визуальной частью, настало время ответить на главный вопрос: **как определить, доступно ли конкретное время для бронирования?**


### Решение: создаём структуру `TimeSlot`

Создадим структуру, которая объединяет время и его доступность:

```swift
struct TimeSlot: Identifiable {
    let id = UUID()
    /// Время записи (9:00 И так далее)
    let time: String
    /// Доступно ли время к записи
    var isAvailable: Bool
}
```

Теперь у нас есть структура данных, которая содержит всё необходимую информацию о бронировании: 

 - Время
 - Доступно ли бронирование
 - Уникальный идентификатор

Ранее, у нас был массив со строками

```swift
let times: [String] = ["9:00", "10:00", "11:00", "12:00", "13:00", "14:00"]
```

Но очевидно, что кнопке не достаточно лишь информации о времени.  
Ей нужно знать ещё и о том – доступна ли запись

Для этого мы и создали `TimeSlot`, который хранит всю требуемую для отображения кнопки информацию.

## Шаг 9. Загрузка данных с сервера

В реальном приложении данные приходят с сервера. Добавим `ViewModel` для управления состоянием:

```swift
// MARK: - ВьюМодель для Основного Экрана

class BookingViewModel: ObservableObject {
    
    /// По умолчанию – пустой массив, но как только вью появится на экране – загрузим с сервера 
    @Published var timeSlots: [TimeSlot] = []
    /// Признак показа индикатора о том, что происходит загрузка
    @Published var isLoading = false
    /// Покажем сообщение об ошибке
    @Published var errorMessage: String?
    
    /// Класс, который занимается тем, что загружает данные с сервера
    private let apiService = APIService()
    
    @MainActor
    func loadTimeSlots() async {
        /// Начинаем загрузку данных
        self.isLoading = true
        
        do {
            /// Получаем данные о времени бронирования с сервера
            let slots = try await apiService.fetchTimeSlots()
            self.timeSlots = slots
        } catch {
            self.errorMessage = error.localizedDescription
        }

       /// Скрываем индикатор загрузки 
       self.isLoading = false
    }
    
    @MainActor
    func bookTime(at slotId: UUID) async -> Bool {
        self.isLoading = true
        
        /// slotId Это айДи кнопки записи, на которую нажал пользователь
        // Находим индекс слота, сравнивая каждый из элементов с выбраным slotId
        guard let index = timeSlots.firstIndex(where: { $0.id == slotId }) else {
	        /// Если такого элемента нет – уходим подальше от сюда
			return
		}
		
		/// Если return не сработал
		/// Значит index существует и мы можем продолжить бронирование
 
        do {
            /// Попытаемся отправить запрос на сервер о том, что пользователь забронировал это время
            try await apiService.bookTime(timeSlots[index].time)
            
            /// Обновляем элемент в массиве благодаря найденному индексу
            /// Теперь состояние кнопки изменилось (Стала недоступным к бронированию)
            self.timeSlots[index].isAvailable = false
            return true
        } catch {
            /// Не получилось забронировать – покажем ошибку
            self.errorMessage = error.localizedDescription
            return false
        }
        self.isLoading = false 
    }
}
```

Зачем нам `slotId` ? Нам нужно понимать на какую именно кнопку нажал пользователь, ведь она у нас не одна. 

В качестве `slotId` мы можем использовать любой уникальный идентификатор, который позволит нам определить нажатую кнопку, мы можем использовать и `time`  ведь у нас не может быть нескольких кнопок с одинаковым временем записи.

Нет смысла дополнительно объяснять словами, что написано кодом. Постарайтесь обдумать каждую строчку. 

## Шаг 11. Обновляем `TimeButtonList` для работы со структурой

Теперь наш список кнопок будет получать массив структур и передавать идентификатор при нажатии:

```swift
// MARK: - Список всех кнопок

struct TimeButtonList: View {
    
    /// Список времён для бронирования
    let timeSlots: [TimeSlot]
    
    /// Комплишен позволит передеть айДи кнопки на основной экран
    /// Что бы основной экран вызвал функцию внутри своей ВьюМодели
    let onBookTime: (UUID) -> Void
    
    var body: some View {
        LazyVGrid(columns: Array(repeating: GridItem(.flexible()), count: 3)) {
            ForEach(timeSlots) { slot in
                TimeButton(
                    time: slot.time,
                    isAvailable: slot.isAvailable
                ) {
                    /// Через Комплишн, передадим информацию на основной экран, о том, что одна из кнопок нажата. 
                    /// Обратите внимание, что мы передаём Id кнопки, что бы понимать какая именно кнпока была нажата.
                    onBookTime(slot.id)
                }
            }
        }
    }
}
```

 `isAvailable` теперь не просто `true` – она зависит от того значения, которое указано в `TimeSlot`.

А так как у нас есть функция `bookTime` внутри `BookingViewModel` наш `isAvailable` – будет зависить от логики внутри данной функции.

Вернитесь к указанной функции и обратите внимание, что как только запрос на сервер выполнился успешно – мы меняем значение `isAvailable` на `false` и кнопка теперь к бронированию не доступна.


## Шаг 12. Финальная версия `BookingView`

Собираем всё вместе:

```swift
// MARK: - Основное Вью, которое собирает всех компоненты на экране воедино 

struct BookingView: View {
    
    @StateObject private var viewModel = BookingViewModel()
    
    var body: some View {
        VStack {
            if viewModel.isLoading {
                ProgressView("Загрузка...")
            } else if let error = viewModel.errorMessage {
                VStack {
                    Text("Ошибка: \(error)")
                        .foregroundColor(.red)
                    Button("Повторить") {
                        Task {
                            await viewModel.loadTimeSlots()
                        }
                    }
                }
            } else {
                Text("Выберите время для записи")
                    .font(.headline)
                    .padding()
                
                TimeButtonList(
                    timeSlots: $viewModel.timeSlots
                ) { slotId in
                   /// Обрабатываем нажатие на одну из кнопок
                   /// Вызов данной строчки происходит через комплишн внутри TimeButtonList
                    Task {
                        await viewModel.bookTime(at: slotId)
                    }
                }
            }
        }
        .onAppear {
            Task {
                 await viewModel.loadTimeSlots()
            }
        }
    }
}
```

> 🎯 **Вывод:** Использование структуры TimeSlot делает код более надёжным, читаемым и лёгким для расширения. Всегда группируйте связанные данные в одну структуру вместо использования нескольких массивов.
